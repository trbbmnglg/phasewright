# Dashboard data: files, JSON and thresholds

All files are in the phased-shipping data folder (`${CLAUDE_PLUGIN_DATA}` in the plugin, `~/.claude/phased-shipping` for the personal copies). `--data` must be an absolute path: an empty or relative `--data` is a usage error (exit 2) and nothing is read or written. They are created on the first write. The folder, `sessions/` and each file must be a real folder or a regular file with one name: a link, a junction or a hard link makes the script stop and write nothing.

The status and list files go to the data folder only. `collect --out` writes the one file you name, and is refused when that file would be inside the data folder (under any name or route, a link or a junction included), when it is a network or device path such as `\\host\share` (on every platform), when its file name has a colon in it, or when a real path is already there that is not a regular file; the page is written to `dashboard.html` in the data folder (see "The page" below), or, with `page.mjs --out <file>`, to the one file you name, under the same refusals; nothing else is written. Do not point `--data` at a folder that git tracks: `projects.json` holds the absolute paths of your projects.

## Off by default

`status.mjs set`, `clear` and the automatic registration done by `set` do nothing, and print `dashboard is off; nothing written`, while the dashboard is off or was never turned on. Only `enable`, `disable`, `asked` and `unregister` write while it is off. An explicit `register` while it is off exits 1, says to run `enable` first and writes nothing. `unregister <id>` works while it is off: it only removes that entry from the list, exits 0, says what it removed and writes nothing else (while the dashboard is on it also rebuilds the page, see "The page" below). `state` and `list` only read.

## The three files

`dashboard.json`: `{ "v": 1, "enabled": false, "asked": null, "warnMin": 90, "idleMin": 180 }`. `asked` is the date the question was answered (`enable`, `disable` and `asked` all set it).

`projects.json`: `{ "v": 1, "projects": [{ "id", "path", "name", "labels", "roadmaps", "added" }] }`, at most 100 projects.
- `id`: the first 12 hex digits of the SHA-256 of the project root's real path (lower-cased on Windows). The project root is the repository: `--root` is the folder that holds `PHASES.md`, and `set`, `clear`, `register` and `unregister` resolve that folder with `realpath`, then walk up from it (the folder itself first, then each parent, at most 40 folders) to the nearest folder that has a `.git` entry, a folder or a file. Only the name is looked for: the entry is never opened, read or followed. The climb stops at your home folder and at the filesystem root, and a `.git` found there is ignored, so a repository that tracks your dotfiles does not swallow everything. On a system with user ids (Linux, macOS) a `.git` that another user owns is not trusted: the climb stops there and the given folder is the project, so a repository of someone else above it never becomes yours; on Windows nothing is checked. With no repository the project root is the folder itself, as before. A `--root` that, seen from the project root, is inside a `.git`, `node_modules` or `.roadmap-backups` folder is refused (exit 1, nothing written). A repository root that is the data folder, is inside it or holds it is not used (the folder itself is), and a folder inside the data folder is refused. So a run in a roadmap subfolder such as `docs/roadmap` belongs to its repository's one project, with the same id as a run in the repository root, and two roadmap folders in one repository are one project with two roadmaps; their sessions are kept per roadmap and phase (see the session file below). Existing entries are never migrated: a command that does not change the list leaves `projects.json` as it is. A stored roadmap that is text but not a usable path (an entry written by an earlier version, such as one inside `node_modules` or `.roadmap-backups`) is left out when the list is read, so it stops no command, and a command that writes the list anyway writes it without that entry; entries that become the same path once cleaned (such as `docs\PHASES.md` and `docs/PHASES.md`, and on Windows two spellings in another letter case) are one, and the first stays; a value that is not text still makes the file "not as expected".
- `path`: the absolute path. This file is the only place an absolute path is written. `list` prints it only with `--paths`, and the merged JSON never holds it.
- `name`: the base name of the project root. `labels`: the `project` values this project's history records use (history is joined by these labels, never by folder name). `roadmaps`: paths of roadmap files relative to the project root, `PHASES.md` by default. When a run names a folder below the project root and that folder holds a `PHASES.md` (a regular file), its path from the project root, such as `docs/roadmap/PHASES.md`, is added (merged, no duplicates, at most 10, plain names, `.md` only, never under `.git`, `node_modules` or `.roadmap-backups`); a `register --roadmap` value is relative to the project root too. A project first seen from a subfolder starts with that path alone: the project root's own `PHASES.md` is not added by a run that found the root by climbing. When a roadmap is not added, the command prints one more line that says why, in fixed words and never with the path: its folder is more than 5 folders below the project root, a folder name has a character that is not allowed (letters, digits and `. _ @ + ( ) -` and space), or the project already lists 10 roadmaps. The collect script reads these nested paths inside the project root like any other.

`sessions/<id>-<phase>.json`, in its current form `sessions/<id>-<tag>+<phase>.json` (or `sessions/<id>-u<tag>+<phase>.json` for an unlisted folder, see below): `{ "v": 1, "project": "<id>", "roadmap", "phase", "phase_name", "step", "state", "step_started", "updated" }`, times in epoch milliseconds, at most 16 KB. `roadmap` is the path of the roadmap file the run is for, relative to the project root with forward slashes (the folder the run passes plus `PHASES.md`, so `PHASES.md` at the project root), checked like the entries of `roadmaps`; `<tag>` is the first 6 hex digits of the SHA-256 of that path, lower-cased only where the file system ignores letter case (Windows and macOS by default; `io.caseInsensitive` is the test seam), so on Linux `Docs/PHASES.md` and `docs/PHASES.md` are two roadmaps with two files. A run in a folder whose roadmap path is not usable (more than 5 folders deep, or a folder name with a character that is not allowed) has no `roadmap` field: its file carries `"unlisted": true` instead, its name has a literal `u` before the 6 hex digits (`<id>-u<tag>+<phase>.json`), and its tag is of a fixed text and the folder's path from the project root, so two such folders do not share a file, and no unlisted name is ever the name of a listed roadmap's file, whatever the tags. The `+` cannot occur in a phase id, so a new name never reads as the older `<id>-<phase>.json` of another phase.
- `step`: `baseline`, `build`, `compare`, `review`, `preview`, `approve`, `ship` or `prod-check`.
- `state`: `working`, `waiting` or `done`.
- The file name is built only from the id, the 6 hex digits of the tag (with the `u` before them for an unlisted folder), a `+` and a phase id matching `[A-Za-z0-9._-]{1,40}` that is not only dots, lower-cased (so `7a` and `7A` are one file on every system; collect compares phase ids without regard to case). One file per project, roadmap and phase: the same phase id in two roadmaps of one repository gives two files, each with its own title, estimate, state and trail, and `clear` removes only its own. The older form (`<id>-<phase>.json`, no `roadmap` field) is read by `collect`, with the same file-name rules, and is never written, taken over or removed by `set` or `clear`: each of them only ever reads, writes or removes its own file (`<id>-<tag>+<phase>.json` or the `u` form). An older file ages out as `Idle` and is then archived like any session. When an older file and a tagged file exist for the same project and phase (the phase compared without regard to letter case), `collect` shows only the newer one by `updated` (a clock-skewed session counts as the oldest, and on a tie the tagged file wins) and drops the other without a word, so a phase is not listed twice after an upgrade. Two sessions on the same phase of the same roadmap share a file (the last write wins). Collect reads the name strictly (a 12-hex id, an optional `u`, a 6-hex tag, a `+` and a lower-case phase id; a name with a capital in its phase is not a session file name): a name whose tag is not that of its `roadmap` field is skipped and reported by base name only, a name with the `u` needs `"unlisted": true` and no `roadmap` field, and a name without it needs a `roadmap` field and no marker; any other mix is skipped and reported by base name.
- `phase_name` is empty unless `set` was given `--name`. The run never passes `--name` (a title from a file must not reach a command line), so a page takes the title from the roadmap row with the same phase id.

The trail (`trail`) is an optional field of a session file: `[{ "step", "state", "at" }]`, the last changes of step or state, with `at` in epoch milliseconds, at most 40 entries.
- A first `set` for a phase writes no trail (the file's own `step`, `state` and `step_started` say it all). A `set` that changes the step or the state appends one entry; a repeated call changes nothing in the trail and only moves `updated`. A file from before the trail existed gets one entry for what it said, then the new one.
- A `set` after `done` starts a new run: the trail starts again, so a rerun is not drawn as a loop back.
- Entries with an unknown step or state, or a time that is not a whole number of milliseconds, are dropped when `set` rewrites the file. Over the 16 KB cap the oldest entries go first and the newest one always stays; the call is refused only when the file is still too large without a trail.
- `collect` skips a session whose trail is not a list of at most 40 valid entries and reports its file name only.

Text fields are cleaned: control, bidirectional, zero-width, tag and other format characters become spaces, one line, at most 200 characters (names and labels 80).

## The merged JSON (`collect.mjs`, schema `v: 1`)

```
{ "v": 1, "generatedAt": "<ISO>", "thresholds": { "warnMin", "idleMin" },
  "projects": [{ "id", "name", "status": "ok" | "not found" | "unreadable",
    "roadmaps": [{ "file", "tables", "standard", "phases": [{ "id", "phase", "status", "kind", "priority", "urgency",
      "estRaw", "estCal", "estimateH", "actual", "commit", "planFile",
      "timestamps": { "started", "previewed", "approved", "shipped" } }] }],
    "history": [{ "phase", "est_h", "actual_h", "check_rounds", "caught_by", "prod_first_pass", "rolled_back", "tokens" }],
    "errors": [{ "file", "reason" }],
    "summary": { "roadmaps", "phasesTotal", "phasesShipped", "legacyFiles", "legacyNames", "active", "working", "waiting", "idle", "archived",
      "estimateActiveH", "workedActiveMs" } }],
  "sessions": [{ "project", "roadmap", "phase", "phase_name", "step", "state", "shown", "noUpdate", "updated", "step_started",
    "loops": [{ "from", "to", "count", "active" }], "rounds", "visits", "workedMs", "elapsedMs", "estimateH", "archived" }],
  "warnings": [{ "kind": "same project, more than one open session" | "clock skew", "project" }],
  "errors": [{ "file", "reason" }],
  "notes": ["older session file(s) not opened"] }   // "notes" is there only when something was not opened
```

- The fields added with the page, for each session (all read from the trail; a session without one has one visit and no loop):
  - `visits`: how many times each step was entered (a step repeated straight away is one visit). `rounds`: the most visits of any one step, 1 when nothing repeated.
  - `loops`: one `{ from, to, count, active }` for each pair of steps with a move back from a later step `from` to an earlier step `to`, `count` times (a rollback from `prod-check` to `build` is one). `active` is true for the latest move back only, while the run is between `to` and `from` and the session is not `done`.
  - `workedMs`: the time spent in `working`, up to the last update (never the time since). `elapsedMs`: from the first entry to the last update.
  - `estimateH`: the calibrated hours of the standard roadmap row with the same phase id (letter case ignored), in the roadmap the session's `roadmap` field names, or null. A session with no `roadmap` field (a file from before), or one that names a file the project does not list, takes the first standard roadmap that has the phase id; a file that is not standard gives no estimate. A session of an unlisted folder has no listed roadmap: no title and no estimate. Each roadmap phase has its own `estimateH`. `roadmap` on a session is that field (null for a file from before, `(unlisted:<tag>)` for an unlisted folder).
  - `archived`: true when the session is `done` and its last update is more than 7 days old. This is this tool's own word for a finished, old session. It is not Claude Code's own archive, which this tool cannot read.
- Each roadmap has `standard`: true when the file has at least one table and every table has the `<!-- phased-shipping:roadmap v1 -->` marker line, false otherwise (a legacy table, a file with two tables of which one has no marker, a file with no table). The data of a file that is not standard is still collected, because the JSON is the data layer; a reader that does not find the field should treat the file as not standard. The field is additive: the schema stays `v: 1`.
- Each project has a `summary`: its standard roadmaps and their phases (`roadmaps`, `phasesTotal` and `phasesShipped` count standard files only), `legacyFiles` (how many roadmap files are not standard) and `legacyNames` (their file names, relative to the project, cleaned, at most 10), its sessions that are working, waiting or idle now, how many are archived, the estimate and the time worked of the active ones.
- No path the tool builds appears in it: files are relative to their project, or base names. Text copied from your files (a phase title, a note) is shown as written, cleaned, with the known forms of this machine's project, data and home folder paths replaced by `[path]` (in string values only, never in a key). The known forms are those paths in any mix of `\`, `/`, a doubled backslash and the URL-encoded `%5C` and `%2F`, any `<drive>:\Users\<name>` (also the 8.3 short name), and `/c/Users/<name>`, `/Users/<name>` and `/home/<name>`; only the part up to and including the name is replaced. Invisible characters are taken out first when that reveals a path. Other spellings of a path may remain, so do not put a path in plan text.
- **Every string is untrusted plain text.** A page must render it as plain text only (escaped in element text, or with `textContent`): no Markdown, no URL attribute (`href`, `src`), no `innerHTML`. As a second layer, `collect` writes `<`, `>`, `&`, U+2028 and U+2029 in the JSON as the escapes `\u003c`, `\u003e`, `\u0026`, `\u2028` and `\u2029`, so the text is safe to inline in a script and parses to the same values (on stdout and in `--out`).
- A roadmap or plan file is read only when its real path is inside the project, it is a regular file (not a link, not a hard link) and it is at most 256 KB. A plan file whose resolved path has a `.git`, `node_modules` or `.roadmap-backups` folder in it is refused, and so is a roadmap entry whose path has one (`not a usable roadmap path`). A file that fails is reported in `errors` by base name and reason, and the rest still loads. A folder that moved is `not found` and stays listed.
- A bad session file is skipped and reported by base name only. Its contents are never copied.
- Caps: 100 projects, 100 sessions, 300 phases and 500 history records per project, 2 MB of output, and 64 MB of project files read in one run (a file past that is skipped and reported). Only a session file of a listed project counts. Every such file name is looked at with an `lstat`, but only the newest 250 by modified time are opened; past 100 sessions the 100 with the newest `updated` time are kept (a clock-skewed session counts as the oldest), and one entry in `errors` says how many sessions that cap left out (a fixed phrase, no file name). The files that were never opened because of the 250 limit are usually old, finished sessions, so they are not an error: a separate entry in `notes` (only then present), `N older session file(s) not opened (only the newest 250 are read)`, says how many, and the page shows it as a quiet note. The sessions cap is 100 so that a page with 40-entry trails and long names stays under its hard limit.

## Thresholds

- `shown` is `Idle` when `updated` is `idleMin` minutes or more ago (default 180). Otherwise it is the state's word: `Working`, `Waiting for you` or `Done`.
- `noUpdate` is true for a working session with no update for `warnMin` minutes or more (default 90).
- A project with more than one open session (shown `Working` or `Waiting for you`) gets the warning.
- A session whose `updated` is more than 5 minutes ahead of the clock, or whose `step_started` is after its `updated`, is clock-skewed: it is shown as `Idle` with `noUpdate: true`, its project gets a `clock skew` warning, and it never counts as an open session.

## The page

`page.mjs --data <dir>` writes `dashboard.html` in the data folder; `status.mjs` rebuilds it in the same process after every `set`, `clear` or `unregister` that worked while the dashboard is on (so an unregistered project's name does not stay in the page). `status.mjs` builds nothing while the dashboard is off, and `disable` leaves the page as it was last written (running `page.mjs` yourself works at any time, on or off, and writes `dashboard.html` then too). A page that cannot be built prints one line, `page not rebuilt (<reason>)`, where the reason is an error code or a short fixed phrase and never a path, and the status call still exits 0. `--refresh-s <5 to 300>` sets the refresh (default 10 s), `--no-fonts` leaves out the fonts, `--out <file>` writes the page elsewhere (refused inside the data folder under any other name or route, refused as a network or device path, and refused when the file name has a colon in it, on every platform, with nothing written). The data folder is never created by it.
- **A big page.** The page has a soft limit of 256 KB and a hard limit of 1 MB. Over the soft limit the Roadmap and Estimate against actual parts of the projects that have no working or waiting session are replaced by one note line (`left out to keep the page small: N rows; the dashboard JSON still has them`), largest saving first, until the page is under 256 KB or nothing is left to drop; if it is still over, the tables of the projects with a running session go the same way. A project's row, its sessions (a waiting one always) and its archived sessions always stay, and a visible line at the top of the page says that something was left out. Over the hard limit of 1 MB (after that) the page is not written: `page not rebuilt (page too large)`, or from the command, `the page would be N KB, over the 1024 KB limit; nothing was written`.

- **Rendered on the server.** The page is built with plain string functions from the merged JSON. It holds no JSON, and no path the tool builds appears in it; text copied from your files is shown as written (known path forms of this machine are replaced), so do not put paths in plan text.
- **JavaScript.** The refresh, the Pause button, the clocks and the 90-minute stale banner need JavaScript; without it the page shows the times as written and a notice, and the refresh text and Pause button are hidden.
- **Escaped.** Every text is cleaned (control, bidirectional, zero-width and other format characters become spaces, one line, a length cap) and then escaped, and goes only into element text or a double-quoted attribute: never into the script, the style, an address, an id or an event handler. Ids and the keys the script stores are generated from a hash. All strings in the JSON and in the page are untrusted plain text.
- **No network.** The page's policy is `default-src 'none'` with `style-src 'unsafe-inline'`, `font-src data:`, `img-src data:` and a `script-src` that names the SHA-256 of its one script. It has no `src`, no outward link, no form and no `base`; the fonts are `data:` urls. The script makes no request, builds no address and writes text with `textContent` only.
- **The script** reloads the page, keeps the clocks running and works out Idle and "No update" in the browser from the times in the page. It keeps the open state of each section as a true or false, the scroll position and the focused row in `sessionStorage`, nothing else.
- **Refresh.** The page reloads every 10 s by default, holds while you select text or hover a cut-off title, and has a Pause button. Each reload restarts the loop animation.
- **Levels.** A project is a closed row with a one-line summary; inside it, the sessions (each with the eight gates of a phase), a Roadmap part, an Estimate against actual part and an Archived sessions part. A project with a working or waiting session starts open.
- **Loop arrows.** Under the eight gates, a right-angled arrow goes from the gate a run left back to the gate it returned to, labelled in text (`x N` and the two step names); a gate entered again says `round N`. Only the loop that is active right now moves (its dashes run); every other arrow is still, and none moves in print or when the browser asks for reduced motion.
- **Archived** means done and more than 7 days since the last update, as under "The merged JSON".
- **The look.** Two colours carry state, each only on borders, strokes and hatching, never on text or a fill: the in-progress colour of the logo (salmon: `#FFB28F` on the dark page, and on the light page the light logo's `#B33A0B`, because the pale one is 1.6:1 against the light page) and the "Waiting for you" accent (a rose `#FF8FAB` on the dark page, a crimson `#A3123A` on the light page, a different tone from salmon). In progress is the logo's diagonal hatch: on the running gate of a session and on the in-progress mark of a roadmap row. While a session is working, the hatch drifts slowly, and the header rule at the top of the sheet is a salmon stripe that flows slowly; with no session working, that rule is the same stripe, still. The drift is CSS only (no second script, so the script's hash is unchanged): it is declared only for a screen and only when the browser has not asked for reduced motion, so it is off with reduced motion and in print; the Pause button also stops it (a `paused` class). Every state keeps its word and its shape (the waiting stamp is a square box with its label); corners are square.
- **Only standardized roadmaps are drawn.** The page draws the tables, the phase counts, the roadmap bar, the Roadmap figure in the title block and the Roadmaps figure of a project row from the standard roadmap files only (see `roadmaps[].standard` above). A project with files that are not standard shows one note inside the project, above its Roadmap part: `N roadmap files not standardized: <names> (not drawn). Standardize them with the roadmap skill, mode standardize.` (at most 10 names, then `and M more`), and its row says `(N not standardized)` after the number of roadmaps. A project with no standard file shows that note, the line `No standardized roadmap yet.` in its Roadmap part and no roadmap bar. Its Estimate against actual part still shows, because it is built from the history: a title is taken from a standard roadmap row only, so a phase that is in no standard roadmap shows its id alone. To fix it, run the roadmap skill in standardize mode on each named file; the next page shows the roadmap. The page draws the rows itself, so the roadmaps, phases and shipped figures are the smaller of the summary's and the rows it draws (shipped is never above the total).
- **The roadmap bar.** Each project row has a slim bar of its standard roadmap phases that mirrors the logo's three squares: shipped is a filled segment, in progress a hatched salmon segment, planned an outlined segment, with widths in proportion to the counts and a label such as `3 shipped, 1 in progress, 3 planned` (the same text is its `aria-label`). A segment with no phases is not drawn; parked phases are not drawn but are named in the label (`, 2 parked`). With no standard roadmap file there is no bar.
- **The title block.** At the bottom of the sheet: when the page was written (the date and time in UTC), the number of projects, phases shipped of all phases of the standard roadmaps across the projects (`23 of 72`), sessions that are active and how many of them wait for you (`2 active, 1 waiting`), archived sessions, the source (`plan, history, status files`), the network (`none`) and the refresh. They are the figures as written when the page was built; the script keeps the numbers on each project row current, not these.
- **The stale-page banner.** It appears when the page file has not been rewritten for 90 minutes, the same time as the per-session "No update" warning (a long build step makes no status call). The number comes from one value in the page builder, which writes it into the page (`data-page-stale-min`) and the banner's placeholder; the script's own default is the same 90.
- **Estimate against actual.** The rows come from the project's history: the newest record of each phase id that has an `actual_h` (its estimate is the record's `est_h`, else the calibrated estimate of the roadmap row with that id; its title is that row's, taken from a standard roadmap only, else the row shows the id alone), in history order, oldest first. Shipped rows of a standard roadmap that have an `Actual` and no row from the history follow. Totals, the over-estimate marking, the first pass, fixed after and rolled back notes, and the bars on one shared scale are as before. The actual hours of a history record come from timestamps, so they include any time the run waited for you.
- **Fonts.** PW Sans and PW Mono are subsets of IBM Plex Sans and IBM Plex Mono, renamed because the SIL Open Font License 1.1 requires a Modified Version not to use the Reserved Font Name "Plex". The family names are PW Sans and PW Mono, the PostScript names start with `PWSans-` and `PWMono-`, and only the copyright and licence records of each font keep the Plex notice, as the licence requires (a test reads both name tables). The licence text is `assets/OFL.txt` next to the script, and the page's first comment names it. `--no-fonts` drops them and the page falls back to the system fonts. The repository's lint skips `.woff2` files as binary, so the font bytes are not scanned as text.

## Limits

- A crashed run leaves its session file. It shows as `Idle` after `idleMin`; nothing deletes it. `clear` removes one, and `unregister` removes a project from the list (its session files stay).
- Opening the file by hand and changing it is allowed; a file that no longer has the expected shape makes the scripts stop and report it instead of guessing.
